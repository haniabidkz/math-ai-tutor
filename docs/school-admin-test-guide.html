LearnAI Tutor – School Platform Test Guide

How to try every new feature: schools, school admin panel, phone sign-in, teachers and sections, trial and paid plans, seats, promotion, reports and the new Super Admin tabs. Written for the product owner. Version 22 October 2026.

Live site: https://learnaitutor.com  ·  Super Admin: /super-admin  ·  School Portal: /login?role=school  ·  School Admin panel: /school-admin
Nothing old changed: existing students, parents and teachers keep their email sign-in and everything they had. Every individual student still has the full curriculum.

Two things to know before testing
1. Today every class has one published chapter (Sets). The default free rule is "the first chapter", so trial students currently see every lesson. To see the lock in action, set Free lessons in each free chapter to 1 or 2 in Super Admin → Schools → Access settings (scenario 6). Set it back to 0 afterwards if you want trial schools to see the whole first chapter.
2. There is no online payment. "Paid" means you marked it: a school's plan is set by you in the Schools tab, and an individual student's Paid tick is in the Users tab.

3. Test scenarios

Tick each box as you go. "You should see" tells you the expected result.

Scenario 1 – Create a school Super Admin

Goal: a new school with its code, a 14-day trial, a seat limit and its first admin.

  1. Sign in at /login with your super admin email and open Schools.
  2. Click New school. Enter the name (e.g. Eagle Public School), city, seat limit 5, keep "14-day free trial".
  3. Fill the first admin: name, mobile number, password. Click Create school.
You should see: a green message "… created with code EAGLE-1" (the code comes from the name), a blue box with the admin's phone and password, and the school in the list with Trial · 14 days left and seats 0 / 5. Creating a second school with the same admin phone is refused: "This phone number already has an account".

Scenario 2 – School admin signs in and sets up classes School Admin

Goal: the school admin reaches only their own school and creates sections.

  1. Open /login?role=school (or the "School admin sign in" button on the home page). Enter the admin's mobile number and password.
  2. On the panel, open Classes & Sections. Create Class 6 / A and Class 7 / A.
  3. Try to create Class 6 / A again.
You should see: the panel header shows the school name and code with Trial · N days left; the Overview shows the trial end date and "0 of 5 seats"; sections 6-A and 7-A appear with 0 students; the duplicate is refused with "Section 6-A already exists".

Scenario 3 – Add a teacher and students School Admin

Goal: accounts created by the school, with passwords shown once.

  1. Teachers tab → Add teacher: name, mobile, leave password blank, tick 6-A. Add.
  2. Students tab → Add student: name, mobile, Class 6, section 6-A. Add.
  3. Students → Bulk import. Paste three lines, one per student: Name, Phone, Class, Section for example:
    Ali Ahmed, 03000000111, 6, A
    Sara Malik, 03000000112, 7, A, Sara2026
    Bad Row, 0300, 6, A
    Click Check rows, then Create 2 accounts.
  4. Click Download logins.
You should see: each new account's phone and generated password in a blue box; the check marks the third row "Phone number is not valid"; the import creates 2 and fails 1; a CSV with the logins downloads; the Students list shows every student with class-section, Free badge, "Not yet" for the diagnostic and Active. The Overview seat bar now says 3 of 5.

Scenario 4 – A student joins with the school code Student

Goal: self sign-up by phone, linked to the school by code; the seat limit holds.

  1. Open /login?role=student&mode=signup (the home page "Get Started" also lands here).
  2. Enter name, mobile, password, Class 6, school code EAGLE-1 (lowercase works too) and a parent's phone. Create Account.
  3. Repeat with two more students to reach the seat limit of 5, then try a sixth.
  4. Try a wrong code, e.g. NOPE-9.
You should see: the student lands on the diagnostic test; the school admin's Students tab lists them in Class 6 (no section yet, the admin can set one); the sixth sign-up is refused with "The school has used all 5 of its seats"; the wrong code says "That school code was not found".

Scenario 5 – Phone sign-in and password reset All roles

  1. Sign out. Sign in as the student with the mobile number (any of these forms work: 03000000111, 0300-0000111, +92 300 0000111) and the password.
  2. Sign in with a wrong password.
  3. As school admin, Students → key icon Reset password on a student; sign in with the new password.
  4. Sign in with an old email account you already had (a demo student or teacher).
You should see: all phone forms sign in; a wrong password says "The phone/email or the password is wrong"; the new password works and the old one does not; email accounts sign in exactly as before.

Scenario 6 – What a trial student can open Student

  1. In Super Admin → Schools → Access settings, set Free lessons in each free chapter to 1 and save.
  2. Sign in as a student of the trial school and finish the diagnostic (or open the dashboard if already done).
  3. Look at "Your 5 active topics" and the Learn page; open the first lesson; then try the second lesson or its quiz.
You should see: a grey "Free lessons" notice on the dashboard explaining the trial; the first lesson opens; later lessons show Paid plan and opening one says "Your school's trial includes the first lesson of the first chapter. Ask your school to upgrade…". The teacher and school admin panels show the student as Free.

Scenario 7 – Paid plan, demo trial and individually paid students Super Admin

  1. Schools → Manage the school → Plan Paid → Save. Reload the student's dashboard.
  2. Set the plan back to Trial, tick Demo trial: open the whole curriculum during the trial → Save. Reload the student.
  3. Untick demo. Then in Users, filter by the school, tick Paid for one student only. Reload that student.
  4. Set Free lessons in each free chapter back to 0 when you are done.
You should see: paid plan → the notice disappears and every lesson opens; demo trial → the same; after unticking demo, only the individually paid student has everything (badge Paid), the others are Free again.

Scenario 8 – Teacher of a school Teacher

  1. Sign in at /login?role=teacher with the teacher's mobile and password.
  2. Look at the dashboard header, the student list and the class filter.
  3. Open Add students and add one to 6-A. Try to reset a 7-A student's password (there is none in the list – that is the point).
  4. Open Homework: pick Class 6, a lesson, "Whole class" and the section 6-A only. Assign.
  5. Sign in as a 6-A student and as a Class 6 student without a section.
You should see: the header shows the school name and plan badge; only 6-A students are listed, each with a section and a Free/Paid badge; the homework appears for the 6-A student but not for the Class 6 student without a section; the teacher cannot see or touch students outside their sections. A teacher with no sections ticked sees the whole school.

Scenario 9 – Expired trial Super Admin Teacher

  1. Schools → Manage → Plan Expired / free → Save (or set the trial end date to yesterday).
  2. Sign in as the school admin and as the teacher. Open Homework as the teacher with Free lessons in each free chapter = 1.
You should see: the panels still work fully; the school admin overview says "Trial ended"; the teacher's Homework tab shows an amber notice and locked lessons with a lock icon that cannot be ticked; assigning a free lesson still works; students keep the free lessons only.

Scenario 10 – Suspend a school, suspend a person Super Admin School Admin

  1. Schools → Manage → Status Suspended → Save. Try the school admin, teacher and student sign-ins.
  2. Set the status back to Active.
  3. As school admin, Students → suspend one student; try to sign in as that student; unsuspend.
You should see: every member of a suspended school is refused with "Your school's account is suspended"; a suspended person sees "This account is deactivated"; after unsuspending, sign-in works again.

Scenario 11 – Remove and delete School Admin Super Admin

  1. As school admin, Students → Remove from school on a student. Check the Overview seats. Sign in as that student.
  2. Teachers → Remove from school on the teacher. Try the teacher sign-in.
  3. As super admin, Users → filter by the school → trash icon on a student → type DELETE.
You should see: the removed student keeps the account and progress as an individual student and a seat is freed; the removed teacher is deactivated ("This account is deactivated"); the deleted student disappears from Users and cannot sign in; the seat is freed.

Scenario 12 – Annual promotion School Admin

  1. Have students in 6-A, 7-A and 8-A. Open Promotion and read the preview table.
  2. Type the school code to confirm and click Promote all classes.
  3. Open Students; switch the filter to Graduated. Try Promotion again.
You should see: the preview lists 6-A → 7-A, 7-A → 8-A, 8-A → Graduated and any sections that will be created; after running, students moved up with their section names kept, Class 8 students are listed under Graduated with all their history, seats count current students only, promoted students are asked to take the new class's diagnostic (if the box was ticked), and a second run within six months needs the "I understand" tick.

Scenario 13 – Reports School Admin Teacher

  1. School admin → Reports. Click Sections (Excel), Students (Excel) and Print / Save as PDF.
  2. Students tab → Export CSV.
You should see: a table per section (students, diagnostic done, quizzes, lessons, average XP, active last 7 days, paid/free) and a table of every student; the CSV files open in Excel; the print view has the school name and date and saves as PDF from the browser's print dialog.

Scenario 14 – Two schools never see each other Isolation

  1. Create a second school (Scenario 1) with its own admin, teacher and students.
  2. Sign in as school B's admin: look at Students, Teachers, Reports. Open /school-admin?schoolId=<school A id> (copy the id from the Open panel link in Super Admin).
  3. Sign in as a student of school A and open Leaderboard; then as a student of school B.
You should see: school B's admin sees only school B; the school A link answers "You can only manage your own school"; each student sees a board with their own school's name and only its students; individual students keep the public board. Homework from school A never reaches school B.

Scenario 15 – Super Admin analytics and users Super Admin

  1. Open Analytics after a day or two of real use.
  2. Open Users: search by phone, filter by school and by role, reset a password, revoke sessions.
  3. Open Leaderboard: choose a school in the first drop-down.
You should see: Active today (DAU), active 7/30 days, regular students (3+ days), signed-up vs diagnostic completed vs drop-offs vs one-lesson completers, paid vs free, school vs individual, a bar per day, most failed questions with their wrong rate, top misconceptions with the lessons they appear in, and a schools table. Users shows School, Class, Plan columns and the new actions. The leaderboard shows the chosen school's board and its reward decision.

5. Limits and decisions to know

  • Classes 6, 7 and 8 only, because the curriculum and diagnostics exist for those. Promotion graduates Class 8. Adding Class 9 later needs content first.
  • Free rule: first chapter(s) of each class, optionally only the first N lessons of each. With one chapter per class live today, use the lesson limit to restrict trials.
  • Individual (old) students stay on the full curriculum unless you untick Paid for them in Users. Unticking also removes them from weekly rewards, as before.
  • Password reset for phone accounts is done by the school admin, teacher (own sections) or super admin; there is no email reset link for phone accounts.
  • Individual teachers who signed up themselves and have no classes ticked still see every individual student (unchanged from before). Tick their classes in Users to limit them.
  • School leaderboards close every Monday like the public board; rewards per school are approved in Super Admin → Leaderboard with the school selected.
  • Trial length, free lessons and default seats are in Super Admin → Schools → Access settings.
